## کنترلر را در مرز نگه دارید

کنترلر باید درخواست HTTP را به یک عملیات برنامه تبدیل کند و نتیجه را به پاسخ برگرداند. قوانین کسب‌وکار را در action یا service متمرکز قرار دهید تا بدون ساختن درخواست وب نیز قابل آزمون باشند.

```php
final class CreateUser
{
    public function handle(CreateUserData $data): User
    {
        return DB::transaction(fn () => User::create($data->toArray()));
    }
}
```

## کوئری‌ها را قابل مشاهده کنید

گران‌ترین مشکلات عملکرد اغلب پشت رابطه‌های راحت پنهان می‌شوند. تعداد کوئری را بررسی کنید، فقط ستون‌های لازم را بخوانید، eager loading را آگاهانه انجام دهید و فهرست‌های روبه‌رشد را صفحه‌بندی کنید. صدها کوئری برای یک صفحه یک نقص نرم‌افزاری است.

## کارهای کند را به صف بسپارید

ایمیل، ورود داده، گزارش و همگام‌سازی سرویس‌های بیرونی معمولاً جایی در چرخه درخواست ندارند. job باید idempotent باشد، با امنیت retry شود و برای عیب‌یابی زمینه کافی در لاگ ثبت کند.

## رفتار را تست کنید

آزمون‌ها را روی دسترسی‌ها، پول، تغییر وضعیت و مرزهای یکپارچه‌سازی متمرکز کنید. مجموعه آزمون کوچکی که قوانین کسب‌وکار را محافظت کند از مجموعه‌ای بزرگ و وابسته به جزئیات پیاده‌سازی ارزشمندتر است.

## جمع‌بندی

لاراول قابل نگهداری به معنای افزودن الگو به همه‌جا نیست؛ یعنی مرزهای روشن، کوئری‌های قابل مشاهده، کارهای پس‌زمینه امن و کدی که شکل دامنه را دنبال می‌کند.
