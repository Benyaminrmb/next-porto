## نوع‌ها باید دامنه را توضیح دهند

بیشترین ارزش TypeScript زمانی نمایان می‌شود که یک نوع، قانونی واقعی از کسب‌وکار را بیان کند. مجموعه‌ای کوچک از نوع‌های روشن و دامنه‌محور بهتر از انتزاع‌های هوشمندانه‌ای است که فقط نویسنده‌شان می‌فهمد.

## فقط وضعیت‌های معتبر را مدل کنید

یونیون‌های متمایز ساختن ترکیب‌های نامعتبر را دشوار می‌کنند:

```typescript
type RequestState<T> =
  | { status: 'idle' }
  | { status: 'loading' }
  | { status: 'success'; data: T }
  | { status: 'error'; message: string }
```

حالا هر شاخه دقیقاً فیلدهای موردنیاز خودش را دارد. با استفاده از `never` نیز می‌توان مطمئن شد که هر وضعیت تازه در تمام شاخه‌ها مدیریت می‌شود.

## جنریک‌ها را هدفمند محدود کنید

جنریک باید اطلاعات مفید را حفظ کند، نه اینکه آن را پاک کند. وقتی یک عملیات واقعاً به ویژگی مشخصی نیاز دارد constraint اضافه کنید و باقی کار را به inference بسپارید.

## مرزهای بیرونی را اعتبارسنجی کنید

نوع‌های استاتیک در مرز شبکه و ذخیره‌سازی متوقف می‌شوند. داده نامطمئن را پیش از تبدیل به مدل دامنه بررسی کنید. ترکیب اعتبارسنجی زمان اجرا و نوع‌های دقیق، قوی‌ترین تضمین را می‌سازد.

## جمع‌بندی

TypeScript خوب سروصدا نمی‌کند؛ خطا را می‌گیرد، بازآرایی را امن‌تر می‌کند و بدون تبدیل سیستم نوع به یک برنامه دوم، هدف کد را توضیح می‌دهد.
