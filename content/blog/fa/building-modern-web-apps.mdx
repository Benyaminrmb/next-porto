## سرور را نقطه شروع قرار دهید

اپلیکیشن‌های مدرن Next.js وقتی بهترین نتیجه را می‌دهند که سرور انتخاب پیش‌فرض باشد. کامپوننت‌های سرور دسترسی به داده را نزدیک منبع نگه می‌دارند، حجم جاوااسکریپت مرورگر را کم می‌کنند و اولین نمایش مفید را سریع‌تر به کاربر می‌رسانند. مرز کلاینت را فقط جایی اضافه کنید که واقعاً به تعامل نیاز است.

## مرز داده را آگاهانه طراحی کنید

داده را در کامپوننتی دریافت کنید که مالک آن است و سیاست کش را صریح انتخاب کنید. صفحه موجودی که هر ساعت تغییر می‌کند نباید همان سیاست صفحه معرفی ماهانه را داشته باشد.

```tsx
export default async function ProjectsPage() {
  const projects = await getProjects()
  return <ProjectList projects={projects} />
}
```

## تغییر داده با Server Actions

وقتی فرم و عملیات آن به هم تعلق دارند، Server Actions انتخاب خوبی است. ورودی را همیشه در سرور اعتبارسنجی کنید، مجوز کاربر را بسنجید، خطای قابل فهم برگردانید و فقط داده‌ای را بازاعتبارسنجی کنید که تغییر کرده است.

## عملکرد، بخشی از محصول است

حجم باندل، ابعاد تصویر، تعداد کوئری و نرخ موفقیت کش را اندازه بگیرید. امکانات فریم‌ورک کمک می‌کنند، اما جای فهمیدن اینکه کاربر دقیقاً منتظر چیست را نمی‌گیرند.

## جمع‌بندی

معماری قدرتمند معمولاً غافل‌گیرکننده نیست: رندر مبتنی بر سرور، جزیره‌های تعاملی کوچک، کش صریح و مالکیت روشن داده.
